# تجهيز سيرفر الكيت عند العميل

## هتحتاج
- `ISTDocAi.KitSetup.exe`.
- كود المنتج وكود العميل، مثلاً `FWD` و `UNF`.
- رابط DocAi، ورابط الـ callback بتاع الكيت.

## الخطوات
افتح Terminal **كمسؤول**، ونفّذ الخطوات دي بالترتيب:

1. **جداول الـ AI في داتابيز الشركة:** وقّف موقع الكيت، وبعدين شغّل:
   ```
   ISTDocAi.KitSetup.exe database
   ```
   - اختار فولدر الموقع، وهو الفولدر اللي فيه `Web.config`.
   - راجع اسم السيرفر والداتابيز، ووافق.
   - هيعمل الجداول، ويتأكد إن الداتابيز دي بتاعة العميل الصح.
   - شغّل الموقع تاني لما يخلص.

   لو مسؤول الداتابيز هو اللي هيشغّل السكربت بنفسه، شغّل `ISTDocAi.KitSetup.exe --export-sql <فولدر>` وابعتله الملف.
2. **التحضير:**
   ```
   ISTDocAi.KitSetup.exe prepare
   ```
   - اختار التطبيق من IIS، واكتب الأكواد والروابط.
   - هيطلّعلك **pairing code**. ابعته لمسؤول DocAi بإيدك، مش في إيميل ولا شات.
3. **التفعيل:** لما مسؤول DocAi يقولك إنه خلّص `apply`، استنى دقيقة، وبعدين شغّل:
   ```
   ISTDocAi.KitSetup.exe activate
   ```
4. **التجربة:** ارفع B/L من Extract with AI، واتأكد إن النتيجة رجعت.

## أوامر تانية
| الأمر | بيعمل إيه |
|---|---|
| `status` | يعرض الحالة، من غير ما يعرض أي أسرار. |
| `pairing` | يعرض نفس الـ pairing code تاني. |
| `cancel` | يلغي التحضير. مسموح بس قبل `activate`. |

## لو حصلت مشكلة
- `ACTION NEEDED`: اعمل اللي مكتوب، وشغّل الأمر تاني.
- `REFUSED`: وقّف، وابعت الرسالة لمسؤول DocAi.
- شهادة HTTPS بتاعة DocAi لازم تكون موثوقة على سيرفر الكيت.
# نشر الأدوات

افتح `ISTDocAi.sln`، وخلي `ISTDocAi.Tools` هو Startup ودوس F5 أو Ctrl+F5 لقائمة النشر بس. اختار الأداة أو All four؛ الناتج في `tools/publish/<Name>` وبيستبدل القديم، فاقفل الـ exe القديم الأول. لازم نسخة الريبو والـ .NET SDK. All four بيكمل باقي الأدوات لو واحدة فشلت وبيطبع ملخص، وبعد النشر تقدر تفتح الفولدر أو تشغل الأداة.

CLI من غير أسئلة: `dotnet run --project tools/src/ISTDocAi.Tools -- publish KitSetup`، أو `publish all`. للـ Debug خلي مشروع الأداة نفسها Startup ودوس F5؛ DevSetup محتاج Visual Studio كـ Administrator.
